# 从字节到页面：大文档的阅读架构

当一份文档从几兆字节增长到一个 GiB，阅读器需要重新思考读取、解析与显示之间的关系。本文记录一种基于**增量索引**和**局部渲染**的实现方式。

> 阅读一份大文档，并不意味着需要把整份文档装进内存。

## 1. 让读取与文件大小解耦

传统阅读器通常先读取完整文本，再生成 HTML。文件越大，等待时间、内存占用和页面布局成本也随之增长。

我们采用不同的读取流程：

1. 获取文件大小、编码和文件身份。
2. 读取首屏所需的少量内容。
3. 在后台扫描结构，建立可复用的磁盘索引。
4. 根据当前位置，只解析视口附近的内容。

### 1.1 按偏移读取

Windows 的 `seek_read` 允许独立读取指定字节位置，避免多个任务争用一个文件游标。偏移量使用 `u64`，读取预算始终有上限。

```rust
pub trait FileSource: Send + Sync {
    fn size(&self) -> u64;
    fn read_at(&self, offset: u64, length: usize)
        -> std::io::Result<Vec<u8>>;
}
```

### 1.2 编码与边界

UTF-8 的多字节字符可能跨越读取缓冲。解码器必须保持完整的字符边界；UTF-16 还需要保留原始字节位置与代理对。

## 2. 建立两级文档索引

文件索引负责回答“当前位置在哪里”，结构索引负责回答“这里应该如何解析”。两者相互配合，避免把数百万个块记录永久保存在内存中。

| 组件 | 存储方式 | 职责 |
| --- | --- | --- |
| 阅读区段 | 固定长度二进制记录 | 定位附近的文本窗口 |
| 标题目录 | 磁盘分页 | 提供 H1–H6 导航 |
| 渲染缓存 | 有预算的 LRU | 复用近期阅读区段 |
| 全文搜索 | 流式扫描 | 增量返回匹配位置 |

### 2.1 保留解析上下文

当视口位于代码围栏中间，局部解析器仍需要知道语言和围栏状态。普通段落优先在空行处形成安全边界。

### 2.2 处理超大语法块

巨型代码块和超长行按固定预算拆分。复杂的列表、表格或 HTML 块超过预算时，保留原文并进入兼容阅读模式。

## 3. 使用分段滚动坐标

浏览器无法布局无限高的页面。因此，阅读位置使用两套坐标：

- **逻辑位置**：文件中的原始字节偏移。
- **物理位置**：当前阅读窗口中的局部像素位置。

接近窗口边缘时加载相邻区段，并保留当前内容的视觉锚点。全局进度条映射整份文档，提供远距离定位。

### 3.1 有界缓存

缓存以实际字节数进行淘汰。代码高亮和图片仅在需要时加载，离开视口的内容可以回收。

```typescript
interface RenderWindowRequest {
  documentId: string;
  byteOffset: number;
  maxBytes: number;
  requestVersion: number;
}
```

### 4.1 交互压力测试

打开大文件后立即跳到末尾，再跳回中间。搜索尚未结束时继续阅读，然后切换文档。这种交错操作更容易暴露过期请求、任务取消和资源释放问题。
